# 에이전트 출고 집계

서버 기동 후 `DailyShipmentArchive`가 `db/init/item_event_daily.sql`을 적용한다.
기존 시연 DB의 `item_event_daily`와 규격·상품 참조는 보존하고, 집계가 없는 DB에서도 원본으로 동작한다.

`/internal/v1/warehouses/{id}` 아래 상품별 출고, 박스 사용, 월별 출고, 출고 상태 조회는
`agent_shipment_history`를 사용한다.

- 과거 날짜에 집계가 있으면 그 집계를 사용한다. 보관 중인 같은 날짜 원본은 다시 세지 않는다.
- 집계가 없는 날짜는 원본을 사용한다. 오늘은 원본을 읽어 신규 출고를 즉시 반영한다.
- `live-` 시연 출고와 아직 도래하지 않은 출고 시각은 에이전트 운영 실적에서 제외한다.
- 박스 사용 충진율은 집계의 충진율 합계를 출고 수로 나눈 가중 평균이다.
- 출고 상태의 마지막 시각은 원본이 있는 마지막 날의 실제 시각을 유지한다.

매일 한국 시각 00:15에 전날 원본이 남아 있는 센터를 집계한다.
DB advisory lock으로 여러 서버의 동시 집계를 막고, 원본이 없는 센터·날짜의 집계는 보존한다.
원본 삭제는 하지 않는다. 거제의 전체 비교 시뮬레이션 이력도 유지된다.
일정은 `chagok.shipments.archive-cron`으로 조정할 수 있다.

## 화면 통계와 일반 수요 계산

일별 `/metrics`와 일반 발주 참고 계산은 `ShipmentHistorySql`의 공통 조회를 사용한다.
DB 테이블·기존 계정·업무 데이터는 교체하지 않는다.

- 집계의 행 수 대신 `sum(shipments)`를 쓰며, 충진율은 충진율 합계 / 유효 출고 수로 계산한다.
- 과거 집계와 보관 원본은 센터·날짜·출처(hist/live)별로 중복을 제거한다.
- 오늘은 집계 스냅샷 대신 실제 발생 시각까지의 원본을 읽는다. 미래 출고는 포함하지 않는다.
- 일반 수요는 현재 상품의 활성 기본 규격을 우선한다. 박스가 없어 대기한 출고도 수요에 포함한다.
- 일반 수요의 시작은 한국 시각 자정으로 맞추고, 오늘 경과 시간까지 포함한 실제 일수로
  월 수요와 안전재고를 환산한다. 저장 결과에 `sourceResolution`, `observedDays`를 남긴다.
- 라이브 수요 포함 여부는 기존 초기화 흐름과 함께 유지한다.
- 시간별 통계·개별 이벤트 재생은 시각·순서가 필요하므로 보관 원본을 사용한다.
- 박스 규격 삭제 시 일별 집계의 참조 이력도 검사해 기존 삭제 불가 사유로 안내한다.

본부장 대시보드는 일별 출고로 계산해 DB에 저장한 월별 본부 리포트 API를 읽는다.
목록·상세 GET은 Spring이 `box_agent.hq_report`를 직접 읽으므로 에이전트 서버 없이도 조회할 수 있다.
리포트가 아직 없는 DB의 목록은 빈 배열이며, 생성·승인에는 기존과 같이 에이전트가 필요하다.
30일 환산 월 효과와 실제 누적 합계는 구분하고, 새 리포트 생성 전에는 마지막 저장 리포트를 표시한다.
새 일반 참고 계산은 배포 후 정기 작업 또는 수동 재계산으로 반영된다. 기존 승인 제안서는 수정하지 않는다.
